# ОС · Лабораторная №1 · Вариант 20

Вариант 20. Родитель создаёт два дочерних процесса. Первые две строки ввода задают имена их выходных файлов. Следующие строки длиной не более 10 символов отправляются первому ребёнку через pipe1, остальные — второму через pipe2. Каждый ребёнок переворачивает полученные строки и записывает их в свой файл через стандартный вывод.

## Исходники

- `parent.cpp` — родитель, два канала и два вызова fork.
- `child1.cpp` — программа первого ребёнка.
- `child2.cpp` — программа второго ребёнка.

Дети выполняют одинаковый алгоритм. У каждого свой процесс, канал и выходной файл. Сборка использует эти три исходника; общие функции находятся непосредственно в них.

## Сборка и запуск в WSL

```bash
g++ -Wall -Wextra -Wpedantic child1.cpp -o child1
g++ -Wall -Wextra -Wpedantic child2.cpp -o child2
g++ -Wall -Wextra -Wpedantic parent.cpp -o parent
./parent
```

Запускайте из этой папки. Введите два разных новых имени файла, каждое на отдельной строке, затем текст. Ctrl+D на пустой строке завершает ввод. Если файл существует, O_EXCL выдаёт ошибку. Для повторного опыта используйте новые имена.

## Алгоритм

В parent.cpp находятся два явных вызова fork и две дочерние ветки. В первой ветке закрываются лишние концы каналов, open создаёт первый файл, dup2 подключает pipe1[0] к стандартному вводу и файл к стандартному выводу. execlp запускает ./child1. Во второй ветке аналогично запускается ./child2 с pipe2 и вторым файлом. Родитель закрывает оба читающих конца и распределяет строки по длине. После завершения ввода он закрывает оба пишущих конца и вызывает waitpid для каждого ребёнка.

Функции read_line, write_all и print_error записаны прямо в исходниках. read_line накапливает строку побайтовым чтением. write_all досылает остаток после частичной записи. При EINTR операции повторяются. signal(SIGPIPE, SIG_IGN) позволяет родителю обработать ошибку записи, если ребёнок закрыл канал. Существующие файлы защищены флагом O_EXCL. Сообщения об ошибках выводятся через write в стандартный поток ошибок. Разрешённый std::string используется для хранения строк.

Ожидается корректный UTF-8. Длина строки измеряется в кодовых точках без перевода строки. Байты продолжения символа UTF-8 находятся в диапазоне от 128 до 191. Родитель считает остальные байты. Ребёнок идёт с конца строки и копирует байты каждого символа в исходном порядке. Так сохраняется поддержка кириллицы. Графемные сочетания из нескольких кодовых точек отдельно не объединяются.

## Проверенный пример

```text
После двух новых имён файлов вводились строки:
1234567890
abcdefghijk

Привет
абвгдежзийк
last

Первый файл:
0987654321

тевирП
tsal

Второй файл:
kjihgfedcba
кйизжедгвба
```

Сборка трёх программ в WSL с -Wall -Wextra -Wpedantic прошла без предупреждений. Автоматическое сравнение результатов подтвердило распределение на границе 10/11 символов, обработку пустой строки, кириллицы и последней строки без перевода. Дополнительно проверены строки до 100000 байтов, 400 коротких строк, пустой набор данных и неверные имена файлов. При повторном использовании имён получена ошибка, прежние файлы сохранили своё содержимое.
